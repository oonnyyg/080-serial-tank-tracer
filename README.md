# 串联全混池示踪分析 (tracer_train)

纯标准库的 Python 工具，计算入口示踪剂浓度变化在一串完全混合池（tanks in
series）中的传播，并对示踪剂质量做收支核对。

## 运行方式

```
python -m tracer_train 输入.json --out 输出目录
```

输入文件可以是单个情景对象，也可以是 `{"scenarios": [ ... ]}` 数组；数组中
每个 `name` 必须唯一。每个情景独立计算，输出：

- `<name>_steps.csv`：初始状态及每个步边界末各池浓度、累计输入/输出质量；
- `<name>_summary.json`：参数、网格、初始/最终存量、累计进出量与收支残差。

## 输入格式

```json
{
  "scenarios": [
    {
      "name": "pulse",
      "volumes": [100.0, 150.0],
      "initial_concentrations": [0.0, 0.0],
      "flow_rate": 10.0,
      "end_time": 60.0,
      "step_size": 5.0,
      "inlet_schedule": [[0, 2.0], [10, 0.0]]
    }
  ]
}
```

字段按水流方向排列，校验规则如下：

- `volumes`：非空数组，每个池体积有限且为正；
- `initial_concentrations`：与体积等长，浓度有限且非负；
- `flow_rate`：所有池共用同一恒定流量，有限且为正；
- `end_time`：终止时刻（秒），有限正数；
- `step_size`：建议数值步长（秒），有限正数；
- `inlet_schedule`：`[time, concentration]` 数组，必须从 0 开始、时间严格
  递增且不超过终止时刻，浓度非负。某节点的新值从该时刻起生效，最后一个值
  一直持续到 `end_time`。

## 离散公式

池内瞬时均匀混合，不考虑反应、吸附与损耗。对第 \(i\) 个池，质量守恒为

\[
V_i \frac{dc_i}{dt} = Q\,(c_{i-1} - c_i),
\]

其中首池入口 \(c_0(t)\) 取入口时间表当前区间的值。时间步 \([t_n, t_{n+1}]\)
（长度 \(\Delta t\)）采用**后向欧拉**：

\[
c_i^{n+1} = \frac{V_i\,c_i^n + Q\,\Delta t\,c_{i-1}^{n+1}}
                  {V_i + Q\,\Delta t}.
\]

关键点：各池不是独立推进的。第 \(i\) 池使用的上游浓度是**同一步步末**的
\(c_{i-1}^{n+1}\)（首池用本区间入口值），因此各池按水流顺序在步内依次求解；
不使用上游旧值 \(c_{i-1}^n\)。

步边界取以下三类点的并集（排序去重）：

1. 从零开始、间隔 `step_size` 的有限正步长网格；
2. 入口浓度变化点，保证任何一步都不跨越变化时刻；
3. 终止时刻 `end_time`（保证被精确记录）。

因此实际最后一步可能短于 `step_size`，变化点附近也会出现短步。

## 质量收支

池内质量为 \(M_i = V_i c_i\)。单步流量按 \(Q\Delta t\) 计算：

- 输入质量：\(Q\Delta t \cdot c_{\text{in}}\)（本区间入口浓度）；
- 流出质量：\(Q\Delta t \cdot c_N^{n+1}\)（末池**步末**浓度，与离散格式
  一致，不是旧浓度）。

残差定义为绝对量，不做归一化：

\[
\text{residual} = M_{\text{final}} - M_{\text{initial}}
                  - M_{\text{in}} + M_{\text{out}}.
\]

由于流入项与流出项与后向欧拉更新严格配套，在浮点误差内残差为 0，且不随
步长变化。

## 单位约定

- 时间：秒（s）；
- 流量：输入体积单位/秒；
- 体积：输入自带的体积单位；
- 浓度：质量/体积，质量单位由输入隐含（如 kg/m³、mg/L）；
- 质量（存量与累计量、残差）：输入隐含的质量单位，程序不换算、不归一化。

## 步长的影响

后向欧拉是一阶隐式格式，无条件稳定但有数值阻尼。`step_size` 越细，浓度
曲线越接近解析解；粗网格会削平、滞后峰值。**不要求不同步长给出相同数值
结果**，这正是需要显式声明步长的原因。无论步长大小，离散质量收支都严格
闭合。入口变化点会自动插入网格，改变 `step_size` 只会改变普通区间的疏密，
不会让积分跨过变化时刻。

## 错误处理

运行前先对全部情景完成校验；任一情景非法即**整批失败**：进程以非零状态
退出，错误信息定位到情景名与具体字段（如 `情景 "x": flow_rate 必须为正数`），
并且不会创建输出文件。
